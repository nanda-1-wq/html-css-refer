HTML Semantics Reference

1. Why Semantic HTML Matters

Semantic HTML means using elements that describe the meaning of the content, not just its appearance. A <header> tells browsers, screen readers, and search engines "this is a header" — a <div> tells them nothing.

BenefitExplanation
AccessibilityScreen readers use semantic structure to help blind users navigate pages
SEOSearch engines understand page structure and rank content appropriately
MaintainabilityCode is easier to read and understand for other developers
Default stylesBrowsers apply appropriate default styles to semantic elements
PortabilityContent degrades gracefully in environments without CSS
<!-- Non-semantic: browser/reader doesn't know what these divs mean --> <div class="top"> <div class="logo">My Site</div> <div class="menu">...</div> </div> <div class="content">...</div> <div class="bottom">...</div> <!-- Semantic: structure is clear to everyone --> <header> <h1>My Site</h1> <nav>...</nav> </header> <main>...</main> <footer>...</footer>

2. Document Landmark Elements

Landmark elements define regions of the page. Screen readers use them as navigation landmarks.

<header>
Represents introductory content or a header for its nearest sectioning ancestor. Can appear multiple times (once for page, once inside <article>, etc.). Usually contains: site logo, page title, primary navigation, search.
<!-- Page-level header --> <header> <h1>My Blog</h1> <nav> <ul> <li><a href="/">Home</a></li> <li><a href="/about">About</a></li> </ul> </nav> </header> <!-- Article-level header --> <article> <header> <h2>Article Title</h2> <p>Published: <time datetime="2024-01-15">January 15, 2024</time></p> </header> <p>Article content...</p> </article>
<nav>
Represents a section with navigation links. Use for primary navigation, table of contents, breadcrumbs. Not every group of links needs a <nav> — only major navigation blocks.
aria-label
Distinguish multiple nav elements: "Main navigation", "Breadcrumb", "Footer navigation"
<!-- Primary navigation --> <nav aria-label="Main navigation"> <ul> <li><a href="/">Home</a></li> <li><a href="/products">Products</a></li> <li><a href="/contact">Contact</a></li> </ul> </nav> <!-- Breadcrumb navigation --> <nav aria-label="Breadcrumb"> <ol> <li><a href="/">Home</a></li> <li><a href="/products">Products</a></li> <li aria-current="page">Laptop</li> </ol> </nav>
<main>
Represents the dominant content of the page — the unique content that differs from page to page. There should be only one <main> per page, and it should not be nested inside <article>, <aside>, <footer>, <header>, or <nav>.
<body> <header>...site header...</header> <nav>...navigation...</nav> <main> <!-- The unique content of this specific page --> <h1>Welcome to My Portfolio</h1> <section>...featured projects...</section> </main> <footer>...site footer...</footer> </body>
<article>
Represents a self-contained, independently distributable piece of content. It makes sense on its own — you could share it without context. Use for: blog posts, news articles, forum posts, product cards, comments, social media posts.
<article> <header> <h2>10 Tips for Learning HTML</h2> <p>By <a href="/author/jane">Jane Doe</a></p> <time datetime="2024-03-15">March 15, 2024</time> </header> <p>Learning HTML is the first step...</p> <footer> <p>Tags: <a href="/tag/html">HTML</a>, <a href="/tag/web">Web</a></p> </footer> </article>
<section>
Represents a generic thematic section of content. Should have a heading. Use when content is logically grouped but doesn't qualify as an <article> or <aside>. If you'd put a heading on it, it's probably a <section>.
<main> <section> <h2>About Me</h2> <p>I'm a web developer...</p> </section> <section> <h2>My Projects</h2> <article>...project 1...</article> <article>...project 2...</article> </section> <section> <h2>Contact</h2> <form>...</form> </section> </main>
<aside>
Represents content that is tangentially related to the main content — a sidebar, pull quote, advertising, related links, author bio. Can appear inside <article> or at page level.
<!-- Page-level sidebar --> <aside> <h2>Related Articles</h2> <ul> <li><a href="#">CSS Basics</a></li> <li><a href="#">JavaScript Intro</a></li> </ul> </aside> <!-- Inside an article: additional information --> <article> <p>The ocean covers 71% of Earth's surface...</p> <aside> <p><strong>Fun fact:</strong> We've explored less than 20% of Earth's oceans.</p> </aside> </article>
<footer>
Represents the footer for its nearest sectioning ancestor. Can appear multiple times. Usually contains: copyright, contact info, links to terms/privacy, author info, related documents.
<!-- Page footer --> <footer> <nav aria-label="Footer navigation"> <a href="/privacy">Privacy Policy</a> <a href="/terms">Terms of Service</a> <a href="/sitemap">Sitemap</a> </nav> <address> <p>Email: <a href="mailto:info@example.com">info@example.com</a></p> </address> <p>&copy; 2024 My Company. All rights reserved.</p> </footer>
<address>
Represents contact information for the nearest <article> or <body> ancestor. Can include physical address, email, phone, social links. Does NOT have to be a postal address.
<address> <p>Written by <a href="/author/jane">Jane Doe</a>.</p> <p>Email: <a href="mailto:jane@example.com">jane@example.com</a></p> <p>Phone: <a href="tel:+15555551234">(555) 555-1234</a></p> <p>123 Main Street, New York, NY 10001</p> </address>

ElementLandmark RoleHow Many Per Page

<nav>navigationMultiple allowed — use aria-label to distinguish

3. Text-Level Semantic Elements

Emphasis & Importance

ElementMeaningRenders AsExample
<strong>Strong importance, seriousness, urgencyBold<strong>Warning:</strong> Hot surface!
<em>Stress emphasis (changes meaning)ItalicNever give up on <em>your</em> dreams
<b>Bring attention (no importance)BoldWe tested the <b>SuperSound 3000</b>
<i>Alternate voice, idiom, technical termItalicA certain <i lang="fr">je ne sais quoi</i>
<mark>Relevant/highlighted in current contextYellow backgroundSearch matched: <mark>HTML</mark>
<small>Side comments, fine print, legalSmaller font<small>&copy; 2024 All rights reserved</small>
⚠️ <strong> vs <b>: Use <strong> for genuinely important content. Use <b> to draw attention without importance (product names, keywords).
<em> vs <i>: Use <em> for stress that changes meaning. Use <i> for technical terms, foreign words, thoughts, ship names.

Inline Edits

<del> and <ins>
<del> marks deleted text. <ins> marks inserted text. Both have cite (URL explaining the change) and datetime attributes.
<!-- Price edit --> <p><del>$99</del> <ins>$49</ins></p> <!-- Document edit with attribution --> <p> <del datetime="2024-01-01" cite="/changelog">Old requirement</del> <ins datetime="2024-03-15">New requirement</ins> </p>

Code & Technical Text

ElementPurposeExample
<code>Inline code fragmentUse <code>color: red;</code> in CSS
<pre>Preformatted text block (preserves whitespace)Used to wrap multi-line <code>
<kbd>Keyboard input by the userPress <kbd>Ctrl</kbd>+<kbd>S</kbd>
<samp>Sample output from a program<samp>Error: file not found</samp>
<var>Mathematical variable or placeholderThe variable <var>n</var> represents count
<!-- Inline code --> <p>To change text color use <code>color: blue;</code> in CSS.</p> <!-- Code block (multi-line) --> <pre> <code> function greet(name) { return "Hello, " + name; } </code> </pre> <!-- Keyboard --> <p>Press <kbd>Ctrl</kbd> + <kbd>C</kbd> to copy.</p> <!-- Program output --> <p>The terminal shows: <samp>$ npm install</samp></p> <!-- Variable --> <p>Area = <var>width</var> × <var>height</var></p>

Superscript, Subscript, and Strikethrough

<sup> — Superscript
Raised text. Use for: exponents, footnote markers, ordinal suffixes.
<p>2<sup>10</sup> = 1,024</p> <p>Einstein&apos;s equation: E = mc<sup>2</sup></p> <p>Monseigneur: M<sup>gr</sup></p> <p>1<sup>st</sup>, 2<sup>nd</sup>, 3<sup>rd</sup></p>
<sub> — Subscript
Lowered text. Use for: chemical formulas, footnotes, variable subscripts.
<p>Water: H<sub>2</sub>O</p> <p>CO<sub>2</sub> is carbon dioxide.</p>
<s> — Strikethrough (no longer relevant)
Text that is no longer accurate or relevant. Use for: old prices, canceled events. Different from <del> which marks edits to a document.
<p><s>Tomorrow's hike starts at noon.</s></p> <p>The hike has been cancelled due to rain.</p> <p><s>$199</s> Now only $99!</p>
<u> — Unarticulated Annotation
Inline text with a non-textual annotation — rendered as underline. Use for: spell-check errors, Chinese proper nouns. Do NOT use for styling (use CSS instead).
<p>The document has <u>speling</u> errors.</p>

4. Quotations & Citations

<blockquote>
Block-level quotation from another source. Browsers visually indent it. Does NOT add quotation marks automatically.
cite
URL of the source (not visible, used by browsers/search engines)
<blockquote cite="https://www.freecodecamp.org/news/learn-to-code-book/"> <p>Can you imagine what it would be like to be a successful developer?</p> <p>To have built software systems that people rely upon?</p> </blockquote> <p>&mdash; Quincy Larson, <cite>How to Learn to Code and Get a Developer Job</cite></p>
<q>
Inline quotation. Browsers add quotation marks automatically (differs by language/locale).
cite
URL of the source
<p> As Quincy Larson said, <q cite="https://www.freecodecamp.org/news/learn-to-code-book/"> Momentum is everything. </q> </p>
<cite>
Marks the title of a creative work being referenced (book, article, movie, song, painting). Renders as italic. Does NOT mark the author's name — only the title.
<p>I just finished reading <cite>The Pragmatic Programmer</cite>.</p> <p>The quote comes from <cite>How to Learn to Code and Get a Developer Job</cite> by Quincy Larson.</p>
📌 Key distinction:
• <q> adds quotation marks automatically — use for short inline quotes
• <blockquote> indents visually — use for longer block quotes
• <cite> is for the title of the work, not the author's name

5. Description Lists

<dl>, <dt>, <dd>
A description list groups term-description pairs. Perfect for: glossaries, metadata, FAQ sections, dictionaries.
<!-- Basic description list (glossary) --> <dl> <dt>HTML</dt> <dd>HyperText Markup Language — defines the structure of web pages.</dd> <dt>CSS</dt> <dd>Cascading Style Sheets — handles the visual presentation.</dd> <dt>JavaScript</dt> <dd>A programming language that adds interactivity to web pages.</dd> </dl> <!-- One term, multiple descriptions --> <dl> <dt>Web Developer</dt> <dd>Someone who builds websites and web applications.</dd> <dd>Can specialize in front-end, back-end, or full-stack.</dd> </dl> <!-- Multiple terms, one description --> <dl> <dt>HTML</dt> <dt>HyperText Markup Language</dt> <dd>The standard language for creating web pages.</dd> </dl>

6. Time & Date

<time>
Represents a specific time (24-hour clock) or date. The datetime attribute gives a machine-readable format while the content can be human-readable.
datetime
Machine-readable format. Used by browsers, search engines, and calendar apps.
<!-- Date only --> <p>Published: <time datetime="2024-03-15">March 15, 2024</time></p> <!-- Time only --> <p>Meeting at <time datetime="14:30">2:30 PM</time>.</p> <!-- Date and time --> <p>Event: <time datetime="2024-12-25T18:00:00">Christmas dinner at 6 PM</time></p> <!-- With timezone offset --> <time datetime="2024-12-25T18:00:00-05:00">Christmas 6 PM EST</time> <!-- Duration --> <p>This video is <time datetime="PT2H30M">2 hours 30 minutes</time> long.</p> <!-- Datetime format reference: YYYY-MM-DD → 2024-03-15 hh:mm → 14:30 YYYY-MM-DDThh:mm:ss → 2024-03-15T14:30:00 PTxHxMxS → PT2H30M (duration: 2 hours 30 min) -->

7. Abbreviations & Definitions

<abbr>
Represents an abbreviation or acronym. The title attribute provides the full expansion, shown as a tooltip.
title
The full form of the abbreviation (shown as tooltip)
<p><abbr title="HyperText Markup Language">HTML</abbr> is the foundation of the web.</p> <p><abbr title="World Wide Web Consortium">W3C</abbr> sets web standards.</p> <p>We use <abbr title="Cascading Style Sheets">CSS</abbr> for styling.</p>
<dfn>
Marks the defining instance of a term — where the term is first defined/explained. Usually the <dfn> is inside a <p> or <dl> that contains the definition.
<p> <dfn>HTML</dfn> (HyperText Markup Language) is the standard language for creating web pages. </p> <!-- dfn with abbr --> <p> <dfn><abbr title="Application Programming Interface">API</abbr></dfn> is a way for programs to communicate with each other. </p>

8. Ruby Annotations

Ruby annotations add pronunciation or translation guides above or beside East Asian characters. Also used for educational content.

<ruby>, <rt>, <rp>
<ruby> wraps the base text and annotation together.
<rt> contains the ruby text (pronunciation/meaning) — displayed above.
<rp> provides fallback parentheses for browsers without ruby support.
<!-- Japanese with pronunciation --> <ruby> 明日 <rp>(</rp><rt>Ashita</rt><rp>)</rp> </ruby> <!-- Displays as: 明日 with "Ashita" above --> <!-- Fallback (no ruby support): 明日 (Ashita) --> <!-- Chinese --> <ruby> 漢 <rp>(</rp><rt>hàn</rt><rp>)</rp> 字 <rp>(</rp><rt>zì</rt><rp>)</rp> </ruby>

9. Figure & Figcaption

<figure> and <figcaption>
<figure> wraps self-contained content referenced from the main text — not just images! Can hold: images, illustrations, code blocks, poems, quotes, tables, diagrams. <figcaption> labels the figure (first or last child of <figure>).
<!-- Image figure --> <figure> <img src="architecture.jpg" alt="Bird's eye view of a modern building"> <figcaption>Figure 1: The Guggenheim Museum in Bilbao, Spain.</figcaption> </figure> <!-- Code figure --> <figure> <pre><code>function add(a, b) { return a + b; }</code></pre> <figcaption>Listing 1: A simple addition function in JavaScript.</figcaption> </figure> <!-- Blockquote figure --> <figure> <blockquote> <p>The best way to predict the future is to invent it.</p> </blockquote> <figcaption>&mdash; Alan Kay</figcaption> </figure>

10. Interactive Elements

<details> and <summary>
<details> creates a collapsible disclosure widget. <summary> is the always-visible label/toggle. When clicked, the rest of <details> expands or collapses. No JavaScript needed.
open
Boolean: the details are expanded by default when present
<details> <summary>What is HTML?</summary> <p>HTML stands for HyperText Markup Language. It's the standard language for creating web pages.</p> </details> <!-- Open by default --> <details open> <summary>Installation Instructions</summary> <ol> <li>Download the installer</li> <li>Run the installer</li> <li>Follow the prompts</li> </ol> </details>
<dialog>
Represents a dialog box or modal window. Use JavaScript to open it.
open
Boolean: dialog is visible
<dialog id="myDialog"> <h2>Confirm Action</h2> <p>Are you sure you want to delete this item?</p> <button onclick="document.getElementById('myDialog').close()">Cancel</button> <button>Delete</button> </dialog> <button onclick="document.getElementById('myDialog').showModal()"> Open Dialog </button>

11. Internal Links & Page Navigation

Anchor Links (Jump-to-Section)
Link to any element on the page by targeting its id.
<!-- Table of Contents at top of page --> <nav aria-label="Table of contents"> <ol> <li><a href="#introduction">Introduction</a></li> <li><a href="#methods">Methods</a></li> <li><a href="#results">Results</a></li> <li><a href="#conclusion">Conclusion</a></li> </ol> </nav> <!-- Target sections --> <section id="introduction"> <h2>Introduction</h2> ... </section> <section id="methods"> <h2>Methods</h2> ... </section>
Skip Navigation Link
A visually hidden link at the top of the page that lets keyboard/screen reader users skip directly to main content. Essential for accessibility.
<!-- Usually hidden with CSS until focused --> <a href="#main-content" class="skip-link">Skip to main content</a> <!-- CSS for skip link (hidden until focused) --> <style> .skip-link { position: absolute; top: -40px; left: 0; background: #000; color: white; padding: 8px; z-index: 100; } .skip-link:focus { top: 0; } </style> <main id="main-content"> ...page content... </main>
