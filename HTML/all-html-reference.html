What Is HTML? — Definition & Purpose

HTML — HyperText Markup Language
HTML is the standard language for creating web pages. It was created by Tim Berners-Lee in 1991 and is maintained by the W3C (World Wide Web Consortium) and WHATWG. The current version is HTML5 (living standard).

HyperText = text that contains links to other documents (hyperlinks).
Markup = a system of tags/annotations that describe how content should be structured.
Language = a formal notation with defined rules and syntax.

What HTML Does (and Does Not Do)

HTML DoesHTML Does NOT Do
Defines the structure of a web pageStyle/design (that's CSS)
Describes the meaning of content (semantics)Interactivity or logic (that's JavaScript)
Creates headings, paragraphs, lists, tables, formsAnimate or add visual effects
Embeds images, audio, videoCommunicate with databases directly
Provides links between pagesHandle user authentication
Adds metadata for browsers and search enginesProcess payments or server-side logic

HTML's Role in the Web Stack

The Three Layers of a Web Page

HTML — Structure & Content: "What is on the page?" (headings, text, images, forms)
CSS — Presentation & Style: "How does it look?" (colors, fonts, layout, spacing)
JavaScript — Behavior & Interactivity: "What does it do?" (clicks, animations, data fetching)

<!-- HTML: defines the content --> <button id="greet-btn">Say Hello</button> <!-- CSS: styles it --> <style> #greet-btn { background: #3498db; color: white; padding: 10px 20px; } </style> <!-- JavaScript: makes it interactive --> <script> document.getElementById("greet-btn").addEventListener("click", () => { alert("Hello, World!"); }); </script>

1995HTML 2.0First formal standard. Added forms.
1997HTML 3.2Tables, applets, text flow around images.
1997HTML 4.0Stylesheets, scripting, internationalization.

How a Browser Renders HTML

Browser Rendering Pipeline

1. Parse HTML → Browser reads the HTML file top-to-bottom and builds the DOM (Document Object Model) — a tree of nodes.
2. Parse CSS → Browser reads stylesheets and builds the CSSOM (CSS Object Model).
3. Combine → DOM + CSSOM = Render Tree.
4. Layout → Calculate exact position/size of every element on screen.
5. Paint → Draw pixels to the screen.
6. Composite → Layer and display the final result.

📌 This is why <script> without defer or async blocks parsing — the browser stops building the DOM until the script executes. Always add defer to your scripts in <head>.

1. What Is HTML & Syntax

HTML Element Syntax
HTML defines the content and structure of web pages. Most elements have an opening tag, content, and a closing tag. Void elements have no closing tag (img, br, hr, input, meta, link, etc.).

Part 2 — HTML Semantics

9. Why Semantic HTML Matters

Semantic HTML uses elements that describe the meaning of content. Benefits: accessibility (screen readers), SEO (search engines), maintainability (readable code).

<!-- Non-semantic (meaningless structure) --> <div class="header"><div class="nav">...</div></div> <div class="content">...</div> <div class="footer">...</div> <!-- Semantic (clear meaning) --> <header><nav>...</nav></header> <main>...</main> <footer>...</footer>

Part 4 — Accessibility

16. WCAG POUR Principles

P — Perceivable

✓ Alt text for images  ✓ Captions for video  ✓ Transcripts for audio  ✓ Color contrast ≥ 4.5:1 (normal text) or 3:1 (large text)  ✓ Don't use color alone to convey information

O — Operable

✓ All features keyboard accessible  ✓ Visible focus indicators  ✓ Skip navigation links  ✓ No content flashing >3 times/second  ✓ Enough time to read content

U — Understandable

✓ lang attribute on <html>  ✓ One logical h1, headings in order  ✓ Labels on form inputs  ✓ Descriptive error messages  ✓ Consistent navigation

R — Robust

✓ Valid HTML  ✓ Semantic elements  ✓ ARIA when HTML isn't enough  ✓ Interactive elements have accessible names

Part 5 — HTML Interview Questions & Answers

21. Core Concepts

Q1: What is HTML and what is its purpose?
Answer: HTML (HyperText Markup Language) is the standard language for creating web pages. Its purpose is to define the structure and content of a web page using elements (tags). HTML tells the browser what is on the page — headings, paragraphs, images, links, forms — but not how it looks (CSS) or how it behaves (JavaScript). It was invented by Tim Berners-Lee in 1991 and the current version is HTML5.
Q2: What is the purpose of <!DOCTYPE html>?
Answer: The DOCTYPE declaration tells the browser which version of HTML the document is written in. <!DOCTYPE html> (case-insensitive) activates standards mode (full HTML5). Without it, browsers may render in quirks mode — an older compatibility mode that mimics bugs from ancient browsers, causing inconsistent rendering. It must be the very first line of every HTML file — it is not an HTML element, just a declaration.
Q3: What is the difference between HTML and HTML5?
Answer: HTML5 is the fifth and current major version of HTML. Key additions over HTML4:

• Semantic elements: <header>, <nav>, <main>, <article>, <section>, <aside>, <footer>
• Media elements: <audio>, <video>, <source>, <track>
• New form input types: date, time, email, url, number, range, color
• New APIs: localStorage, sessionStorage, Canvas, Geolocation, Web Workers
• Removed: Presentational elements like <font>, <center>, <big> (moved to CSS)
• HTML5 is now a living standard maintained by WHATWG — updated continuously with no discrete versions.
Q4: What is the difference between block-level and inline elements?
Answer:

Block-level elements start on a new line and take the full available width. They can contain other block and inline elements. Examples: <div>, <p>, <h1>–<h6>, <ul>, <table>, <section>, <article>

Inline elements flow within text, taking only as much width as their content. They cannot contain block elements. Examples: <span>, <a>, <strong>, <em>, <img>, <code>

In HTML5, this distinction became more nuanced — it's now called content categories (flow content, phrasing content, etc.), but the block/inline mental model is still useful and widely used.
Q5: What is the difference between id and class attributes?
Answer:

id — Unique identifier. Must appear only once per page. Used for CSS targeting, JavaScript selection, and anchor links (href="#section-id"). High CSS specificity.

class — Reusable label. The same class can be applied to multiple elements, and one element can have multiple classes (space-separated). Lower CSS specificity than id.

<h2 id="about">...</h2> — unique, referenced by anchor link
<p class="intro highlight">...</p> — reusable, two classes applied
Q6: What is the difference between <div> and <span>?
Answer: Both are generic containers with no semantic meaning, used purely for grouping/styling with CSS or targeting with JavaScript.

<div> — block-level container. Creates a line break before and after. Used for layout sections.
<span> — inline container. Flows within text. Used to style a portion of text.

Rule of thumb: If you can use a semantic element instead (<section>, <p>, <em>, etc.), prefer it over <div>/<span>.

22. Semantic HTML Questions

Q7: What are semantic HTML elements and why do they matter?
Answer: Semantic elements clearly describe their meaning to both the browser and the developer — unlike <div> and <span> which have no meaning.

Examples: <header>, <nav>, <main>, <article>, <section>, <aside>, <footer>, <figure>, <time>, <strong>, <em>

Why they matter:
• Accessibility: Screen readers use landmarks to help users navigate
• SEO: Search engines better understand page structure and rank relevant content
• Maintainability: Code is easier to read and understand
• Default browser styling: Appropriate styles applied without CSS
Q8: What is the difference between <strong> and <b>? Between <em> and <i>?
Answer:

<strong> — marks text as having strong importance, seriousness, or urgency. Has semantic meaning. Screen readers may announce it differently.
<b> — draws attention to text (keywords, product names) without implying importance. No semantic weight.

<em> — marks text with stress emphasis that changes the meaning of a sentence ("I never said that"). Screen readers change tone.
<i> — marks text in an alternate voice: technical terms, foreign words, idiomatic phrases, thoughts. No emphasis on meaning.

Both pairs render the same visually (bold/italic), but the semantic difference matters for accessibility and meaning.
Q9: What is the difference between <article> and <section>?
Answer:

<article> — self-contained content that makes sense on its own and could be distributed independently (blog post, news article, forum post, product card, comment). Ask: "Can I take this and share it on another site?" If yes → <article>.

<section> — thematic grouping of content that needs the page context to make full sense. Should have a heading. Used to divide a page into logical regions.

Articles can contain sections, and sections can contain articles. The key test: can the content stand alone?
Q10: What are void (self-closing) elements?
Answer: Void elements are HTML elements that cannot have any children (content) and therefore have no closing tag. They are complete as a single opening tag.

Examples: <img>, <input>, <br>, <hr>, <meta>, <link>, <area>, <source>, <track>, <wbr>, <embed>, <col>, <base>

In HTML5, you write them without a slash: <img src="...">. The XHTML-style <img /> slash is optional and harmless but not required.

23. Forms & Tables Questions

Q11: What is the difference between GET and POST in forms?
Answer:

GET — Data is appended to the URL as query string (/search?q=html&page=2). Visible in URL. Bookmarkable. Cached by browsers. Use for: search, filtering, non-sensitive queries. Limited URL length (~2000 chars).

POST — Data is sent in the request body, not visible in URL. Not cached or bookmarked. Use for: login forms, registration, file uploads, any data that changes server state, sensitive data (passwords). No size limit.

Rule: If the form retrieves data → GET. If it creates/modifies/deletes data or handles sensitive info → POST.
Q12: What is the difference between disabled and readonly on form inputs?
Answer:

disabled — The input is completely non-interactive: greyed out, cannot be focused, cannot be tabbed to, and its value is NOT submitted with the form.

readonly — The input is not editable, but the user can focus it, tab to it, and copy its value. Its value IS submitted with the form.

Use disabled when the field shouldn't participate at all. Use readonly when you want to show a value that will be submitted but shouldn't be changed (e.g., a calculated total).
Q13: Why should you always use <label> with form inputs?
Answer:

1. Accessibility: Screen readers announce the label when the input is focused, so users know what to enter.
2. Usability: Clicking the label focuses/activates the input — increases click target size, especially helpful for checkboxes and radio buttons.
3. Programmatic association: The for/id link creates a semantic relationship understood by assistive technologies.

Placeholder text alone is not a substitute — it disappears when the user starts typing, leaving them without context.
Q14: What is the difference between colspan and rowspan?
Answer:

colspan — Merges cells horizontally across columns. <td colspan="3"> occupies 3 column widths in one row.

rowspan — Merges cells vertically across rows. <td rowspan="2"> spans from its row down into the next row.

When using rowspan, you must omit the spanned cell in the rows below — the spanning cell already occupies that space. Forgetting this shifts all subsequent cells to the right.
Q15: What is the purpose of <fieldset> and <legend>?
Answer: <fieldset> groups related form controls together with a visible border. <legend> provides the group's title (must be its first child).

Critical for accessibility: When a screen reader enters a fieldset, it reads the legend first — this is the only way users know what a group of radio buttons or checkboxes is asking. Without a fieldset + legend, a radio group with options "Yes / No" gives no context about what you're answering yes or no to.

Bonus: adding disabled to <fieldset> disables all its inputs at once.

24. Attributes & Elements Questions

Q16: What is the purpose of the alt attribute on <img>?
Answer: The alt attribute serves three purposes:

1. Accessibility: Screen readers read alt text aloud to describe the image to blind users.
2. Fallback: Displayed when the image fails to load (broken link, slow connection).
3. SEO: Search engines index alt text to understand image content.

Rules: Meaningful images need descriptive alt text. Decorative images should use alt="" (empty string — not missing!) so screen readers skip them. Never write alt="image" or alt="photo". Describe content AND purpose in context.
Q17: What is the difference between <script defer> and <script async>?
Answer: Both allow the script to download in parallel with HTML parsing (non-blocking download). They differ in when execution happens:

defer — Executes after the HTML is fully parsed, in document order. Scripts run in the order they appear. Best for most scripts that need the DOM.

async — Executes as soon as downloaded, potentially interrupting HTML parsing. Order not guaranteed. Best for independent scripts (analytics, ads) that don't depend on DOM or other scripts.

Neither attribute (inline script) — Blocks HTML parsing until the script executes. Avoid for external scripts.
Q18: What are data-* attributes and how do you use them?
Answer: Custom data attributes let you store extra information in HTML elements that doesn't need a visual representation. They follow the format data-anything="value".

In HTML: <button data-product-id="42" data-category="shoes">Buy</button>

In JavaScript: Access via the dataset property. Attribute names are converted to camelCase: data-product-id → element.dataset.productId.

Common uses: storing IDs for AJAX requests, configuration for JavaScript components, tracking data for analytics.
Q19: What is the viewport meta tag and why is it important?
Answer: <meta name="viewport" content="width=device-width, initial-scale=1.0">

Without it, mobile browsers render the page at a desktop width (~980px) and then scale it down — making text tiny and requiring zooming. The viewport meta tag tells mobile browsers to set the viewport width equal to the device's actual screen width, enabling proper responsive design with CSS media queries.

width=device-width — Use the physical screen width.
initial-scale=1.0 — Don't zoom in or out on first load.

It is required in every HTML page intended for mobile devices.
Q20: What are HTML entities and when do you need them?
Answer: HTML entities are special codes for characters that would otherwise be misinterpreted by the browser or are hard to type. Format: &name; or &#number;

Must use:
• &amp; → & (bare & inside HTML can confuse the parser)
• &lt; → < (would start a tag)
• &gt; → > (would end a tag)
• &quot; → " (inside attribute values wrapped in double quotes)

Useful for symbols: &copy; → ©, &euro; → €, &nbsp; → non-breaking space, &mdash; → — (em dash)

25. Accessibility & Best Practice Questions

Q21: What is ARIA and when should you use it?
Answer: ARIA (Accessible Rich Internet Applications) is a set of HTML attributes that add accessibility information that native HTML can't convey — especially for custom interactive widgets.

The first rule of ARIA: Don't use ARIA if you can use a native HTML element or attribute with the same semantics. A <button> is always better than a <div role="button">.

Use ARIA when:
• Building custom widgets (tabs, modals, accordions, sliders)
• Adding labels to icon buttons: aria-label="Search"
• Announcing dynamic content: aria-live="polite"
• Communicating state: aria-expanded="false", aria-invalid="true"
• Linking descriptions: aria-describedby="hint-id"
Q22: What is tabindex and when should you use it?
Answer: tabindex controls keyboard focus behavior:

tabindex="0" — Makes a non-interactive element (like a <div>) focusable via Tab key in natural document order. Use when you can't use a native interactive element.

tabindex="-1" — Removes element from Tab sequence but allows JavaScript to focus it (element.focus()). Use for modal dialogs and programmatic focus management.

tabindex="1+" (NEVER use) — Creates a separate tab order that overrides natural flow, resulting in confusing navigation for keyboard users.

Best practice: Native interactive elements (<a>, <button>, <input>, etc.) are naturally focusable — don't add tabindex="0" to them.
Q23: What is the difference between <del> and <s>?
Answer: Both render as strikethrough text, but they have different semantic meanings:

<del> — marks content that has been deleted from a document as part of an edit. Used with <ins> to show document changes. Has cite and datetime attributes for attribution. Screen readers may announce "deleted".

<s> — marks content that is no longer accurate or relevant but hasn't been removed (e.g., an old price, a cancelled event). Not an edit marker — just outdated content.

Use <del> for document diffs/track changes. Use <s> for "was $99, now $49" or a cancelled event announcement.
Q24: What makes a web page accessible? Name at least five practices.
Answer:

1. Set the lang attribute: <html lang="en"> — screen readers use this for correct pronunciation.
2. Descriptive alt text: All meaningful images have alt text describing content and purpose.
3. Proper heading structure: One h1, logical hierarchy, no skipped levels — screen reader users navigate by headings.
4. Label all form inputs: Every input has an associated <label> via for/id or nesting.
5. Keyboard accessibility: All functionality works with Tab, Enter, Space, and arrow keys — no mouse required.
6. Visible focus indicators: Never set outline: none without a visible replacement.
7. Sufficient color contrast: Normal text ≥ 4.5:1 ratio, large text ≥ 3:1.
8. Video captions: <track kind="captions"> inside <video>.
9. Skip navigation link: Lets keyboard users bypass repeated navigation.
10. Semantic HTML: <nav>, <main>, <article>, etc. provide landmarks screen readers can navigate.
Q25: What is the difference between <link> and <a>?
Answer:

<link> — Goes in <head>. Defines a relationship between the document and an external resource. Most commonly used to link CSS stylesheets. Void element — no closing tag. Not visible to the user. Also used for: favicon (rel="icon"), canonical URL (rel="canonical"), preloading resources.

<a> — Goes in <body>. Creates a clickable hyperlink that the user sees and interacts with. Links to another page, a file, an email address, a phone number, or a section on the current page.

In summary: <link> is for machine-to-machine resource relationships in the head. <a> is for user-facing navigation in the body.
